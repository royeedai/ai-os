# /align

当用户提出一个新项目、模糊想法、复刻目标、老项目需求变更，或任何“先把方向说清”的任务时触发。

## 目标

在开始设计和编码前，把以下内容说清并写入 `MISSION.md`：

- 目标到底是什么
- 谁会使用 / 验收
- 现在属于哪种项目模式：`greenfield` / `reverse-spec` / `brownfield` / `change`
- 质量优先级是什么
- 已经有哪些输入，哪些还不确定

## 必做步骤

1. 识别当前任务是项目级、模块级，还是局部变更
2. 判断项目模式：
   - 从想法起步：`greenfield`
   - 参考截图 / API / 源码：`reverse-spec`
   - 先接手现有仓库：`brownfield`
   - 已有项目上的变更：`change`
3. 明确用户目标、成功标准、范围内 / 范围外内容
4. 明确质量优先级：逻辑正确、关键体验、工程可维护、交付速度的先后次序
5. 明确已知输入和待确认项
6. 生成或更新 `.ai-os/MISSION.md`
7. 生成或更新 `.ai-os/STATE.md`，记录当前阶段、当前目标、待确认项和最小阅读集

## 输出

- `.ai-os/MISSION.md`
- `.ai-os/STATE.md`
- 下一步建议：是否进入 `/design`，还是先补素材 / 先做 brownfield 结构梳理

## 禁止事项

- 禁止在目标、用户和成功标准不清时直接进入大规模实现
- 禁止把“用户一句话需求”自动脑补成完整产品定义
- 对明确的局部改动，禁止默认先全仓分析
