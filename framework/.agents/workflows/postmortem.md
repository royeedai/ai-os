# /postmortem

当项目交付、里程碑结束、重大问题关闭或需要系统复盘时触发。

## 目标

完成完整复盘，并把稳定结论沉淀进 `.ai-os/memory.md`。

## 必做步骤

1. 读取 `MISSION.md`、`DESIGN.md`、`tasks.yaml`、`acceptance.yaml`、`STATE.md`、交付证据与相关问题记录
2. 引导复盘至少覆盖：
   - 交付结果
   - 问题根因
   - 踩坑记录
   - 优化方向
   - 规则 / 流程迭代建议
3. 区分"稳定结论"和"临时观察"
4. 将稳定结论同步更新到 `.ai-os/memory.md`
5. 审查 `memory.md` 中的现有活跃条目，将已被取代、已失效或不再影响当前开发的条目归档到归档区（参照 `memory-manager` skill 的归档策略）
6. 在 `STATE.md` 中记录本轮复盘已完成及后续跟进项

## 输出

- 复盘摘要
- 需进入 `memory.md` 的稳定经验
- 归档条目清单（如有）
- 后续优化建议

## 禁止事项

- 禁止只写结果，不分析根因
- 禁止把未经确认的猜测沉淀进 `memory.md`
- 禁止复盘完成后不更新项目记忆
- 禁止直接删除 memory 条目；不再有效的条目必须归档而非删除
