# /design

当 Mission 已经明确，但关键页面、信息架构、关键交互、视觉方向或关键流程还没锁定时触发。

## 目标

先把“做成什么样”说清，再进入完整开发。

## 必做步骤

1. 读取 `.ai-os/MISSION.md` 和 `.ai-os/STATE.md`
2. 确认 `MISSION.md` 已是最新且已获得用户确认；若需求仍在变更，先转 `/change-request`
3. 确认本轮必须先锁的关键页面 / 关键流程 / 核心接口旅程 / 核心设计决策
4. 生成或更新 `.ai-os/DESIGN.md`：
   - 信息架构
   - 关键页面与交互
   - 关键流程
   - 视觉方向
   - 核心设计决策、备选方案与取舍理由
   - 设计确认记录
5. 如果是 `reverse-spec` 模式，生成或更新 `.ai-os/design-pack/parity-map.md`
6. 显式区分“必须用户确认的核心决策”和“AI 可自行处理的非核心细节”
7. 把已锁定内容、待确认项、确认停点写回 `.ai-os/STATE.md`
8. 向用户输出 `DESIGN.md` 核心内容、预设逻辑、选型依据和待确认项，等待明确确认
9. 若关键设计仍未确认，暂停在此，不进入 `/plan` 或 `/build`

## 输出

- `.ai-os/DESIGN.md`
- `.ai-os/design-pack/parity-map.md`（reverse-spec 适用）
- 更新后的 `.ai-os/STATE.md`

## 禁止事项

- 没有关键页面和流程定义，不得声称“可以开始完整开发”
- 禁止把视觉细节未定等同于逻辑可直接开工
- 禁止技术栈、架构、数据结构、页面结构、核心交互等核心决策未经确认就直接写代码
