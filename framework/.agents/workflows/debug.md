# /debug

当用户要求修复单一 bug、微调样式 / 文案 / 配置，或定位一个明确问题时触发。

## 目标

用最小但完整的流程完成“先定方案再动手”，避免越界修复和改 A 坏 B。

## 必做步骤

1. 读取 `.ai-os/STATE.md`、相关 `MISSION.md` / spec / 任务上下文，确认本次问题没有超出 `P2` 边界
2. 明确：
   - 复现路径或现象
   - 当前假设或已确认根因
   - 影响范围
   - 计划修改的文件和模块
   - 是否触及核心逻辑、已确认设计或关键依赖
3. 向用户输出修复方案、边界说明、风险和验证计划
4. 等待用户明确回复“确认修复方案，可执行”
5. 只修改直接相关代码；若执行中发现问题超出原边界，立即暂停并升级到 `/change-request` 或 `/design`
6. 完成后验证：
   - 目标问题已解决
   - 影响范围内相关功能已回归
   - 没有引入新的已知回归
7. 更新 `.ai-os/STATE.md`，必要时同步 spec / acceptance 中的验证记录

## 输出

- 修复方案与边界说明
- 修改后的验证和回归结论
- 是否需要升级为更高治理档位

## 禁止事项

- 禁止在未给出根因 / 假设、影响范围和文件边界前直接改代码
- 禁止顺手重构、统一风格或修改无关逻辑
- 禁止多个独立改动点混在一次修复里静默推进
- 禁止不做回归就宣称修复完成
