## 5.5 User Journey 闭环契约

> 凡涉及"前端 UI 消费后端接口"的模块，必须列出该模块所属的端到端 user journey 链路；每条 journey 必须有至少一个 E2E-SMOKE 任务承接，验收标准是真实跑通而不是单点接口看起来对。
> 详见 `framework/.agents/references/derived-rules.md` 2.4 节与 PL-035。

| Journey ID | 用户路径（自然语言） | 途经的全部接口 (method × path) | 关键前端消费点 | 单点接口产出字段 → 下游消费字段映射 | E2E-SMOKE 任务 ID |
|------------|------------------|---------------------------|------------|---------------------------------|----------------|
| J-001 | [示例：保存数据集 → 跳到编辑页 → 预览数据] | [POST /datasets, GET /datasets/{id}/preview] | [datasetId 路由参数, columns/rows/total 表格] | [POST 返回 data.id → 前端 res.id → URL /editor/{id}] | [TASK-AI-XXX] |

**Journey 链路设计原则**：

- 每个接口完成时必须显式声明"此接口产出的 X 字段被下游 Y 处消费"
- 任何单点接口不允许以"局部看起来对了"为完成标准
- 端到端 journey 必须在 `/plan` 阶段就有独立任务承担，不能依赖"前后端各自做完了自然就通"
