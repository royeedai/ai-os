# CSV 批量导入 Spec

## 1. 模块概述

- **模块目标**：在现有商品后台中补齐 CSV 批量导入能力
- **所属阶段**：plan
- **关联 Mission / Design**：MISSION.md / DESIGN.md
- **关联需求点 ID / 标题**：REQ-001 / CSV 批量导入

## 2. 业务规则与目标

- **核心规则**：导入前必须校验、去重并输出逐行结果报告
- **必须优先保证的正确性**：导入正确率和错误可追溯
- **允许延后处理的细节**：模板下载与历史批次查询
- **本轮非目标 / 禁止越界项**：不改商品编辑和展示链路

## 3. 界面 / 接口 / 命令清单

- **交互模式**：sync
- **推荐模式理由**：当前变更以后台上传和同步结果反馈为主
- **拒绝的交互模式**：streaming / event-driven

| 编号 | 类型 | 名称 | 描述 | 验收点 |
|------|------|------|------|--------|
| I-001 | 页面 / API | 批量导入入口 | 上传 CSV 并返回逐行结果报告 | AC-001 |

## 4. 关键流程与状态流转

1. 运营上传 CSV
2. 系统执行格式校验与去重
3. 写入合法商品数据
4. 返回成功数、失败数和错误行明细

## 5. 数据与契约

- **契约基准**：MISSION.md + 现有上传链路
- **输入**：CSV 文件、SKU、商品字段
- **输出**：导入统计、错误行报告
- **关键字段 / 状态枚举**：batchId、successCount、failedCount、rowErrors
- **字段映射/适配说明**：沿用现有商品校验规则与上传协议
- **集成触点**：商品管理后台、上传接口、校验规则
- **持久化 / 外部依赖**：商品目录后台
- **受影响模块 / 文件边界**：spec、tasks、acceptance

## 6. 边界条件与异常处理

- CSV 超过最大行数
- 重复 SKU 合并策略
- 部分行失败时的结果返回

## 7. 验收与证据

- **关键用户任务 / 运营任务验证**：运营完成一次可回溯的批量导入
- **设计一致性证据**：导入入口和结果反馈说明
- **逻辑正确性证据**：校验、去重、报告路径说明
- **工程质量证据**：validate 与静态校验
- **运行态证据**：导入链路验证
- **异常/空数据证据**：超限、重复 SKU、部分失败证据
- **回归范围**：商品导入链路及其边界
