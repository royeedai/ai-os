# 代码约定

## 命名约定

- **函数命名模式**：动词开头 camelCase
- **变量 / 常量命名**：局部变量 camelCase，常量 UPPER_SNAKE_CASE
- **文件 / 目录命名**：按导入链路语义命名

## 代码模式

- **数据获取**：沿用现有上传与商品校验链路
- **错误处理**：逐行错误要结构化返回，不吞错
- **状态管理**：导入结果按任务级状态回写

## 导入与分层

- **允许的导入方向**：页面 / 入口 -> 服务 -> 适配层
- **禁止的跨层依赖**：不直接绕过现有上传包装层

## 日志约定

- **日志框架**：沿用现有后台方案
- **日志级别使用**：导入失败至少记录 warning
- **必须包含的上下文**：文件名、批次、错误行

## 禁止模式

- 不把变更类需求直接写成代码实现
- 不顺手改商品编辑和展示链路
