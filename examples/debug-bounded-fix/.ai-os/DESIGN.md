# Dropdown Empty Fix Design

## 1. 设计目标

- **本轮设计目标**：明确下拉框为空问题的修复边界
- **需要先锁定的关键页面 / 交互**：AiChat 页面模型选择下拉框
- **必须用户确认的核心设计决策**：是否只修本页还是扩大到同类组件
- **允许 AI 自行处理的非核心细节**：局部命名和条件判断
- **允许后补的细节**：全局同类问题排查

## 2. 信息架构

- **入口与导航骨架**：AiChat 页面模型选择入口
- **一级 / 二级结构**：页面初始化 -> 加载模型列表 -> 渲染下拉框
- **关键上下文切换点**：页面初次加载
- **关键信息优先级**：模型列表可见 > 错误提示清晰

## 3. 关键页面与交互

| 页面 / 入口 | 目标 | 关键元素 | 关键操作 | 是否核心决策 | 确认状态 |
|-------------|------|----------|----------|--------------|----------|
| AiChat 模型选择 | 正常展示模型列表 | 下拉框、加载逻辑 | 页面加载 / 选择模型 | yes | pending |

## 4. 关键流程

1. 页面初始化请求模型列表
2. 全局拦截器拆包响应
3. 组件消费模型数据并渲染下拉框
4. 请求失败时给出明确提示

## 5. 视觉方向

- **视觉参考**：沿用当前页面样式
- **信息密度 / 布局原则**：不改布局，只恢复数据
- **组件与交互风格**：沿用现有 Select 组件
- **明确不采用的风格**：不做样式重构
- **与既有设计系统或参考对象的差异**：无

## 6. 设计确认记录

- 2026-03-22：确认只修复下拉框数据加载，不改页面结构
- 2026-03-22：待确认是否需要全局排查同类问题

## 7. 差异与待确认项

- **相对参考对象的明确差异**：仅做单点修复
- **仍待确认的设计项**：是否扩大修复范围
- **执行边界与非目标**：不顺手改 request 层

## 8. 方案选型依据

- **为什么选择当前方案**：问题根因在局部消费逻辑，先锁单点边界
- **备选方案与放弃原因**：全局重构 request 层越界
- **与需求基准的对应关系**：直接对应下拉框为空修复

## 9. 核心约束

- **必须遵守的技术 / 产品约束**：遵守全局响应拆包约定
- **共享基础设施约定**：request interceptor 已拆包 response
- **不可越过的范围边界**：只修改 AiChat 页面相关逻辑
- **依赖前提**：修复方案已确认

## 10. 风险与注意事项

- **主要风险**：误判为全局请求层问题
- **注意事项**：先验证是否还有同类组件受影响
- **触发升级到 change-request / review 的条件**：需要扩大到全局修复
