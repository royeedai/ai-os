# 后台列表与详情编辑 Spec

## 1. 模块概述

- **模块 / 功能名**：后台列表、详情与编辑流程
- **所属交付主题**：基于截图和 API 样例还原后台管理系统
- **交互模式**：reverse-spec，对照截图、API 样例和 parity-map 驱动
- **推荐模式理由**：先锁关键页面结构、关键行为和允许差异，再进入实现
- **拒绝的交互模式**：不采用“只看截图做静态像素还原”的方式

## 2. 业务规则与目标

- **核心目标**：后台运营人员可以在列表页完成筛选、进入详情并完成编辑回流
- **规则 1**：列表筛选条件切换后表格结果要同步更新
- **规则 2**：详情页必须保留与参考对象一致的关键字段分组
- **规则 3**：编辑成功返回列表时必须保留筛选上下文

## 3. 界面 / 接口 / 命令清单

| 入口 | 类型 | 说明 | 关键输入 | 关键输出 |
|------|------|------|----------|----------|
| 列表页 | 页面 | 浏览和筛选数据 | 查询条件 | 表格结果、详情入口 |
| 详情页 | 页面 | 查看记录详情 | 记录 ID | 详情信息、编辑入口 |
| 编辑弹层 / 页面 | 页面 | 修改关键字段 | 记录 ID、编辑表单 | 保存结果、回流状态 |

## 4. 关键流程与状态流转

1. 进入列表页并加载默认结果
2. 调整筛选条件并更新表格
3. 点击记录进入详情页
4. 从详情进入编辑流程并提交
5. 保存成功后返回列表并恢复筛选上下文

## 5. 数据与契约

- **契约基准**：列表查询参数、详情字段分组和编辑提交字段以当前 API 样例为准
- **字段映射/适配说明**：如宿主项目字段名不同，必须在 adapter 层显式映射
- **集成触点**：列表查询 API、详情 API、编辑保存 API、导航状态同步

## 6. 边界条件与异常处理

- **异常/空数据证据**：空结果、详情缺字段、编辑保存失败、无权限编辑
- 筛选为空时显示明确空态，不清空筛选区
- 详情缺字段时保留字段位并显示缺省态
- 编辑失败时保留当前表单输入并提示原因

## 7. 验收与证据

- 关键页面要有 screenshot-compare / behavior-note 证据
- 关键流程要有 contract-baseline-check、degraded-path-check 和人工核对结果
