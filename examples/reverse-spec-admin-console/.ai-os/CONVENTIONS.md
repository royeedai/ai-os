# 代码约定

> reverse-spec 场景优先记录会影响“对照一致性”和“差异显式化”的项目级规则。

## 命名约定

- **页面 / 组件命名**：按业务入口命名，不用 screenshot1、page2 之类临时名
- **字段映射命名**：参考对象字段与宿主项目字段差异要明确标注 adapter 名称
- **文件 / 目录命名**：列表、详情、编辑分模块组织

## 代码模式

- **对照实现**：关键页面先对齐 parity-map 与 spec，再进入实现
- **差异记录**：允许改写的差异必须落在 DESIGN 或 spec，不在代码里暗改
- **状态回流**：列表筛选条件和详情 / 编辑回流行为要在实现前先锁定

## 导入与分层

- **允许的导入方向**：页面 -> 模块 -> 请求适配层
- **禁止的跨层依赖**：页面组件不直接依赖原始 API 样例结构

## 日志约定

- **日志框架**：沿用宿主项目默认前端埋点 / 日志方案
- **日志级别使用**：关键筛选和编辑提交失败需可追踪
- **必须包含的上下文**：当前筛选条件、记录 ID、关键操作来源

## 禁止模式

- 只对照截图做视觉还原而不锁接口与行为
- 未确认允许差异前自行改写核心流程
- 把流程推进语句写进 Mission 当前交付目标
