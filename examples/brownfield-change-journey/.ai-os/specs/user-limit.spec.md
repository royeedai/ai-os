# 用户次数限制 Spec

## 1. 模块概述

- **模块目标**：为既有用户操作补上次数限制与提示
- **所属阶段**：plan
- **关联 Mission / Design**：MISSION.md / DESIGN.md
- **关联需求点 ID / 标题**：REQ-CHANGE-001 / 次数限制与提示

## 2. 业务规则与目标

- **核心规则**：达到上限后必须阻止操作并给出明确提示
- **必须优先保证的正确性**：不影响其他模块链路
- **允许延后处理的细节**：限制策略配置化
- **本轮非目标 / 禁止越界项**：不做全局重构

## 3. 界面 / 接口 / 命令清单

- **交互模式**：sync
- **推荐模式理由**：当前为局部同步校验与提示
- **拒绝的交互模式**：streaming / async-job / event-driven

| 编号 | 类型 | 名称 | 描述 | 验收点 |
|------|------|------|------|--------|
| I-001 | 页面 / API | 用户操作入口 | 触发限制校验并展示提示 | AC-CHANGE-001 |

## 4. 关键流程与状态流转

1. 用户触发受限操作
2. 系统检查当前次数
3. 超限则拒绝并提示
4. 未超限则继续原链路

## 5. 数据与契约

- **契约基准**：MISSION.md + 现有 API 约定
- **输入**：用户操作、已有计数状态
- **输出**：允许继续或限制提示
- **关键字段 / 状态枚举**：remainingCount、limitReached
- **字段映射/适配说明**：沿用现有 DTO / adapter
- **集成触点**：用户操作接口、提示组件
- **持久化 / 外部依赖**：现有 Web 系统 API
- **受影响模块 / 文件边界**：spec、tasks、acceptance

## 6. 边界条件与异常处理

- 计数状态为空时的默认策略
- 并发触发限制时的一致性
- 提示展示失败时的兜底行为

## 7. 验收与证据

- **关键用户任务 / 运营任务验证**：触发限制后被正确拦截
- **设计一致性证据**：提示与拦截方式说明
- **逻辑正确性证据**：边界与异常路径说明
- **工程质量证据**：validate 与静态校验
- **运行态证据**：限制命中验证
- **异常/空数据证据**：计数缺失与并发触发验证
- **回归范围**：受影响入口与提示链路
