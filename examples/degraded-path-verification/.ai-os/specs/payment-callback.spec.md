# 支付回调 Spec

## 1. 模块概述

- **模块目标**：实现支付网关回调处理并补齐异常路径验证
- **所属阶段**：verify
- **关联 Mission / Design**：MISSION.md / DESIGN.md
- **关联需求点 ID / 标题**：REQ-001 / 支付回调全路径处理

## 2. 业务规则与目标

- **核心规则**：回调必须先验签，再按订单状态机决定是否更新
- **必须优先保证的正确性**：重复回调幂等、异常路径不静默失败
- **允许延后处理的细节**：退款回调
- **本轮非目标 / 禁止越界项**：不改支付发起和对账系统

## 3. 界面 / 接口 / 命令清单

- **交互模式**：event-driven
- **推荐模式理由**：支付回调由外部网关异步推送
- **拒绝的交互模式**：streaming / sync CLI

| 编号 | 类型 | 名称 | 描述 | 验收点 |
|------|------|------|------|--------|
| I-001 | API | 支付回调入口 | 接收并处理支付网关回调 | AC-001 |

## 4. 关键流程与状态流转

1. 接收支付回调
2. 验签并检查请求体
3. 根据订单当前状态决定是否更新
4. 记录审计与异常路径结论

## 5. 数据与契约

- **契约基准**：支付网关回调协议 + 现有订单状态机
- **输入**：callbackId、orderId、gatewayStatus、signature
- **输出**：状态更新结果、审计记录
- **关键字段 / 状态枚举**：pending、paid、failed、timeout
- **字段映射/适配说明**：网关状态映射到订单状态机
- **集成触点**：支付回调入口、订单服务、审计日志
- **持久化 / 外部依赖**：支付网关、订单服务
- **受影响模块 / 文件边界**：状态机、审计、acceptance

## 6. 边界条件与异常处理

- 空 body 回调
- 验签失败
- 重复回调
- 已关单订单收到成功回调
- 网关超时

## 7. 验收与证据

- **关键用户任务 / 运营任务验证**：支付回调在异常情况下仍有明确处理结果
- **设计一致性证据**：状态流转与异常路径设计说明
- **逻辑正确性证据**：幂等与异常路径验证结论
- **工程质量证据**：validate 与静态校验
- **运行态证据**：支付回调验证
- **异常/空数据证据**：每条 degraded-path 的证据
- **回归范围**：支付回调入口与订单状态机
