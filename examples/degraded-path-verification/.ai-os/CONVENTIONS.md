# 代码约定

## 命名约定

- **函数命名模式**：动词开头 camelCase
- **变量 / 常量命名**：变量 camelCase，状态常量 UPPER_SNAKE_CASE
- **文件 / 目录命名**：按支付回调语义命名

## 代码模式

- **数据获取**：回调入口统一走验签与状态判断
- **错误处理**：异常路径必须可追踪，不静默吞错
- **状态管理**：所有状态变更先对照状态机

## 导入与分层

- **允许的导入方向**：入口 -> 领域服务 -> 持久化 / 审计
- **禁止的跨层依赖**：状态更新不得绕过幂等与审计层

## 日志约定

- **日志框架**：沿用支付服务默认方案
- **日志级别使用**：异常和重复回调至少记录 warning
- **必须包含的上下文**：callbackId、orderId、gatewayStatus

## 禁止模式

- 不只验证 happy path 就宣称完成
- 不绕开幂等和审计逻辑直接改状态
