# 代码约定

> 本示例还处于设计前置阶段，约定只记录会影响后续实现方向的项目级规则。

## 命名约定

- **函数命名模式**：语义化 camelCase
- **变量 / 常量命名**：变量 camelCase，常量 UPPER_SNAKE_CASE
- **文件 / 目录命名**：按页面或模块语义拆分

## 代码模式

- **数据获取**：在接口层集中定义，不在页面内散写请求协议
- **错误处理**：主流程与异常路径在实现前先映射到 spec
- **状态管理**：优先让状态流转在 spec 中先锁定

## 导入与分层

- **允许的导入方向**：页面 -> 模块 -> 基础设施
- **禁止的跨层依赖**：页面不直接依赖底层适配细节

## 日志约定

- **日志框架**：沿用宿主项目默认方案
- **日志级别使用**：关键流程异常必须可追踪
- **必须包含的上下文**：页面入口、关键状态、失败原因

## 禁止模式

- 未确认页面结构前直接写业务实现
- 把流程型目标冒充交付目标
