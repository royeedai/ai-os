# 首页与主流程 Spec

## 1. 模块概述

- **模块目标**：定义首页结构与主流程，作为后续设计和实现的基线
- **所属阶段**：plan
- **关联 Mission / Design**：MISSION.md / DESIGN.md
- **关联需求点 ID / 标题**：REQ-001 / 首页结构与主流程

## 2. 业务规则与目标

- **核心规则**：首页需清晰表达产品价值、主入口和关键转化路径
- **必须优先保证的正确性**：主流程步骤与异常中断恢复路径完整
- **允许延后处理的细节**：视觉微调与次级页面
- **本轮非目标 / 禁止越界项**：不进入业务代码实现

## 3. 界面 / 接口 / 命令清单

- **交互模式**：sync
- **推荐模式理由**：当前阶段以页面结构与主流程确认为主
- **拒绝的交互模式**：streaming / async-job / event-driven

| 编号 | 类型 | 名称 | 描述 | 验收点 |
|------|------|------|------|--------|
| I-001 | 页面 | 首页 | 展示价值主张、关键模块和主入口 | AC-001 |

## 4. 关键流程与状态流转

1. 用户进入首页
2. 阅读价值主张并识别主入口
3. 进入主流程
4. 出现空状态或中断时给出恢复路径

## 5. 数据与契约

- **契约基准**：MISSION.md + DESIGN.md
- **输入**：产品目标、首页信息层级、主流程定义
- **输出**：首页模块划分与流程说明
- **关键字段 / 状态枚举**：入口状态、流程中断状态、恢复提示
- **字段映射/适配说明**：当前阶段以产品结构映射为主
- **集成触点**：首页入口、主流程入口
- **持久化 / 外部依赖**：无
- **受影响模块 / 文件边界**：DESIGN.md、acceptance.yaml、tasks.yaml

## 6. 边界条件与异常处理

- 空数据状态下首页展示
- 主流程中断后的恢复路径
- 未确认页面不进入编码

## 7. 验收与证据

- **关键用户任务 / 运营任务验证**：产品负责人可确认首页与主流程
- **设计一致性证据**：DESIGN.md 设计确认记录
- **逻辑正确性证据**：流程说明与异常路径说明
- **工程质量证据**：validate 通过
- **运行态证据**：不适用
- **异常/空数据证据**：空状态与中断恢复说明
- **回归范围**：Mission / Design / Tasks / Acceptance 一致性
