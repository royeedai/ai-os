# 代码约定

> 本文件记录 quickstart Todo CLI 的最小一致性基准。

## 命名约定

- **函数命名模式**：动词开头的 camelCase，如 `loadTodos`、`saveTodos`
- **变量 / 常量命名**：局部变量 camelCase，常量 UPPER_SNAKE_CASE
- **文件 / 目录命名**：CLI 入口和模块使用短横线或语义文件名

## 代码模式

- **数据获取**：所有文件读写集中在 store 层
- **错误处理**：命令层把文件和参数错误转成可读提示
- **状态管理**：不引入全局状态，命令执行时现读现写

## 导入与分层

- **允许的导入方向**：命令层 -> store 层
- **禁止的跨层依赖**：store 层不反向依赖命令层

## 日志约定

- **日志框架**：不单独引入日志框架
- **日志级别使用**：CLI 错误直接输出到 stderr
- **必须包含的上下文**：失败命令和目标 Todo ID

## 禁止模式

- 不在命令层直接操作 JSON 文件
- 不吞掉文件权限或格式错误

## 跨层契约登记表

> CLI 单栈项目，大部分跨层契约类别不适用；五节仍然保留以显式登记"暂无"的判定，避免后续新增模块时漏登记。

### HTTP 状态码 ↔ 业务码 ↔ 客户端行为映射

- 暂无（CLI 无 HTTP 状态码）

### Wire 类型契约

- `id` 字段：JS Number（<= 2^53），单用户本地使用不涉及跨语言序列化

### 名单型常量的反向真理源

- 暂无

### 敏感数据 service 方法语义档位

- 暂无

### 中间件 / 查询引擎方言契约

- 暂无（直接 JSON 文件读写，无查询引擎）
