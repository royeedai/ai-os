# 代码约定

> 这是高风险场景示例，约定优先收敛会影响资产安全、审计和发布验证的项目级规则。

## 命名约定

- **状态枚举命名**：使用可审计的领域词汇，不使用模糊缩写
- **事件 / 审计字段命名**：请求 ID、幂等键、操作者、状态来源必须语义明确
- **文件 / 模块命名**：按扣减、审计、补偿三个子域拆分

## 代码模式

- **状态流转**：统一通过状态机入口推进，不允许页面或调用方私自跳状态
- **并发控制**：幂等校验与状态写入放在同一事务边界
- **补偿逻辑**：补偿路径必须与主流程同样保留审计证据

## 导入与分层

- **允许的导入方向**：入口层 -> 领域服务 -> 审计 / 持久化适配
- **禁止的跨层依赖**：控制器不直接拼装数据库更新和审计明细

## 日志约定

- **日志框架**：沿用宿主项目统一日志方案
- **日志级别使用**：扣减失败、补偿触发和鉴权异常必须可搜索
- **必须包含的上下文**：requestId、idempotencyKey、operatorId、stateFrom、stateTo

## 禁止模式

- 在未确认并发策略前直接实现状态写入
- 把 fallback 结果写成正式交付结论
- 在 build 阶段临时改动审批边界或任务 owner
