# 权益扣减状态流转 Spec

## 1. 模块概述

- **模块 / 功能名**：权益扣减状态流转
- **所属交付主题**：权益扣减与状态流转重构
- **交互模式**：后台运营触发 + 服务端状态机执行
- **推荐模式理由**：高风险链路需要显式锁定接口契约、状态枚举和补偿路径
- **拒绝的交互模式**：不采用“先做页面再补逻辑”的弱约束方式

## 2. 业务规则与目标

- **核心目标**：扣减请求在高并发下仍然只能成功落账一次，并留下完整审计链路
- **规则 1**：请求必须携带幂等键
- **规则 2**：成功状态不可逆，失败进入可补偿状态
- **规则 3**：审计日志写入失败时不能伪装成成功交付

## 3. 界面 / 接口 / 命令清单

| 入口 | 类型 | 说明 | 关键输入 | 关键输出 |
|------|------|------|----------|----------|
| `/benefits/deduct` | API | 发起权益扣减 | requestId, userId, amount, idempotencyKey | deductionId, state |
| `/benefits/deduct/{id}` | API | 查询扣减状态 | deductionId | state, auditTrail |
| 审计回放页 | 页面 | 查看扣减链路 | deductionId | 审计事件序列 |

## 4. 关键流程与状态流转

1. 创建扣减请求并校验鉴权
2. 校验幂等键并写入扣减记录
3. 扣减成功时进入 `SUCCEEDED`
4. 扣减失败时进入 `FAILED_PENDING_COMPENSATION`
5. 补偿执行后进入 `COMPENSATED`

## 5. 数据与契约

- **契约基准**：`requestId`、`idempotencyKey`、`state`、`auditTrail` 字段必须稳定
- **字段映射/适配说明**：运营后台只消费服务层已拆包后的执行结果，不直接拼装数据库字段
- **集成触点**：正式鉴权、账户服务、审计日志表、补偿 worker

## 6. 边界条件与异常处理

- **异常/空数据证据**：重复提交、鉴权失败、审计写入失败、补偿超时
- 幂等键重复时返回已存在结果，不重复扣减
- 权限不足时直接拒绝，不进入状态机
- 审计写入失败时标记为失败并触发补偿评估

## 7. 验收与证据

- 需要记录并发 / 权限 / degraded-path 验证证据
- 需要记录合同基准核对、静态校验和运行态验证结果
