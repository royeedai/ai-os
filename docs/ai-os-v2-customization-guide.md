# AI-OS 项目管理优化版使用指引

## 1. 核心目标与适用范围

这次优化的目标，不是增加流程，而是守住项目管理底线：先确认需求，再锁设计，再拆任务，再开发验证。它适用于前端、后端、全栈、工具类、小程序等所有通用开发项目。

## 2. workflow 选择与分级管控

- `P0` 新项目 / 新模块 / 大范围变更：`/align -> /design -> /plan -> /build -> /verify -> /ship`
- `P1` 小功能新增或非核心变更：先 `/change-request`，再按需要进入 `/design` 或 `/plan`
- `P2` 单点 bug / 微调：先 `/debug`，确认边界后修复并回归
- 需要正式审查：`/review`
- 项目或里程碑收尾：`/postmortem`

## 3. 核心管控节点

用户重点确认 4 个地方：

1. `/align` 后确认需求基准
2. `/design` 后确认设计方案
3. `/plan` 后确认任务清单与验收标准
4. `/change-request`、`/debug` 后确认变更 / 修复方案

## 4. 长期维护与资产沉淀

- `MISSION.md` + `specs/` 始终是唯一需求真理源
- `STATE.md` 负责恢复上下文和确认停点
- `memory.md` 只沉淀稳定决策、通用约定和踩坑经验
- 每次复盘用 `/postmortem` 把稳定结论写回 `memory.md`

## 5. 常见问题与注意事项

- 不要按聊天内容直接改代码，先同步基准
- `debug` 不是捷径，超出单点边界就升级
- 未经用户确认，AI 不应自行推进到下一阶段
- 这次优化没有改 CLI 核心源码，只增强规则、workflow 和模板，兼容原生架构与后续升级
